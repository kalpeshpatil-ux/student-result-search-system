Frequently Asked Viva Questions (Oral Examination Prep)

Q1: Why does Binary Search strictly require the roll numbers to be sorted?

Binary Search relies on the monotonic order property. When comparing target key with arr[mid], if arr[mid] < key, we can only guarantee that all elements to the left (0 .. mid) are also smaller than key if and only if the array is sorted. If unsorted, the target could be hiding in either half, breaking the divide-and-conquer strategy.

Q2: When would you ever prefer Linear Search over Binary Search in real-world engineering?

1. Unsorted Data with Infrequent Searches: Sorting an unsorted array takes O(n log n) time. If you only search once or twice, doing a linear search O(n) is much faster than sorting first.
2. Very Small Arrays (N < 20): Cache locality, absence of branch mispredictions, and simple loop overhead make Linear Search competitive or faster on tiny sets.
3. Linked Lists: Binary search requires O(1) random access (arr[mid]). Linked lists require O(n) traversal just to reach the midpoint.

Q3: How do you prevent integer overflow when calculating the midpoint?

In languages like C, C++, and Java with fixed 32-bit integers, calculating mid = (low + high) / 2 can overflow if low + high > 2,147,483,647. The safe calculation is: mid = low + ((high - low) / 2).

Q4: What is the space complexity difference between Iterative and Recursive Binary Search?

Iterative Binary Search uses O(1) auxiliary space since it only maintains three pointer variables (low, mid, high). Recursive Binary Search allocates a new call frame on the execution call stack at each division, resulting in O(log n) stack space.
